# 桌面安全设计与当前边界

- 本地工具栏和远程服务使用不同的渲染环境。远程内容没有 preload、Node.js 或客户端 IPC 权限。
- 主进程只接受本地固定工具栏主框架的少量预定义 IPC 命令；不提供执行命令、任意读取文件或任意 IPC 通道。
- 启用 contextIsolation、sandbox、webSecurity，禁用 nodeIntegration 和混合内容。
- 配置服务只允许 HTTPS 根地址；导航匹配确切服务来源，不用容易误判的字符串前缀匹配。
- 外部链接只允许已列出的 HTTPS 文档/仓库地址；禁止 file、javascript、data 等外部协议导航。
- 远程网页请求默认拒绝设备权限和剪贴板读取；允许当前服务正常复制经过清洗的文本。
- 下载由当前服务发起，通过系统保存对话框选路径；下载文件不会自动执行。文件名移除路径分隔符和 Windows 保留设备名。
- 最近30条已完成下载的信息只保存在本机应用数据目录；登录 Cookie 保存在 Electron 的独立持久会话中，不会复制到 GitHub。
- 本地配置和下载记录没有被当作密码保管库；不要在服务地址中填账号、密码或令牌。

当前桌面端仍是连接云端的客户端，不提供本机监听端口或局域网匿名文件服务器。该选择保留了现有二维码无需收件电脑开机的使用方式。

尚未完成 Apple Developer ID 公证、Windows 证书签名、大规模公网压力测试。请将初版作为小范围试用，而非可用性保证。

实现参考：[Electron 官方安全建议](https://www.electronjs.org/docs/latest/tutorial/security)。

账号验证在云端完成，不开放第三方账号登录页面。密码使用带随机盐的PBKDF2-HMAC-SHA512派生，登录会话使用HttpOnly/Secure/SameSite Cookie，注册/登录/恢复有服务端频率限制。账号恢复会轮换恢复密钥并撤销旧会话。云端代码仍需部署在HTTPS并正确保护数据库与存储。
